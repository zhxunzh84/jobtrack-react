# Phase 1 Proposal: JobTrack

**Module 2 React Group Project** · Two members · Planned effort: 5–8 hours per member outside class

## App Name

**JobTrack — Job Application Tracker**

## Problem Statement

Job seekers applying to multiple companies can lose track of their applications and statuses. JobTrack is a small React app that helps them record, view, and manage applications in one place.

## Target Users

Job seekers managing multiple job applications.

## Core Features

- View all job applications (Read).
- Add an application using a controlled form with required-field validation (Create).
- Delete an application (Delete).
- Filter by status: All, Applied, Interview, Offer, or Rejected.
- Display loading, empty, and error states; show feedback when saving or deleting fails.
- Navigate between the application list and add-application form.
- Persist applications through MockAPI so records remain after a page refresh.

## Routes

| Route               | Purpose |
| ---                 | --- |
| `/applications`     | View, filter, and delete applications |
| `/applications/new` | Add an application; return to the list after a successful save |

The root path `/` redirects to `/applications`. A shared navigation bar links to both pages.

## Data Model

```json
{
  "id": "1",
  "company": "Citi",
  "jobTitle": "Application Support AVP",
  "status": "Applied",
  "appliedDate": "2026-09-20",
  "notes": "Applied through company website"
}
```

`id` is generated by MockAPI. Company, job title, status, and applied date are required; notes are optional. Dates use `YYYY-MM-DD`. Status is one of `Applied`, `Interview`, `Offer`, or `Rejected`, defaulting to `Applied`.

## Data Source and Stack

Use **MockAPI**, a hosted mock backend listed in the assignment brief, to practise REST requests without building a server. Use sample application records for the demo.

| Method | Resource            | Purpose               |
| ---    | ---                 | ---                   |
| GET    | `/applications`     | Load applications     |
| POST   | `/applications`     | Create an application |
| DELETE | `/applications/:id` | Delete an application |

The team will configure the actual endpoint and check service limits before implementation.

**Stack:** React, Vite, JavaScript, React Router, native `fetch`, basic CSS, Git/GitHub, and Vercel for public deployment.

## Planned Component Structure

```text
App
├── Navbar
└── Routes
    ├── ApplicationsPage
    │   └── ApplicationList
    │       └── ApplicationCard
    └── AddApplicationPage
        └── ApplicationForm
```

`App` owns shared application data and request handlers using `useState`, and loads records with `useEffect`. Data and callbacks pass through props. `ApplicationsPage` owns the status filter; `ApplicationForm` owns controlled input state. No Context or reducer is needed for this scope.
